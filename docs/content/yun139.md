# Yun139

[Yun139](https://yun.139.com) is the personal cloud storage service offered by
China Mobile (中国移动), also marketed as "MCloud" or "和彩云". It offers a
personal (个人云) and a family (家庭云) space with web, mobile and PC clients.

Rclone accesses Yun139 through the same "personal_new" and family
orchestration APIs used by [OpenList](https://github.com/OpenListTeam/OpenList).
You need an authorization token to configure the backend.

## Configuration

Here is an example of making a yun139 remote called `remote`. First run:

```console
rclone config
```

Then follow through the interactive setup:

```text
No remotes found, make a new one?
n) New remote
s) Set configuration password
q) Quit config
n/s/q> n

Enter name for new remote.
name> remote

Option Storage.
Type of storage to configure.
Choose a number from below, or type in your own value.
[snip]
XX / China Mobile Cloud Drive (中国移动云盘)
   \ (yun139)
[snip]
storage> yun139

The 139 authorization token. Base64 of "pc:<account>:<token>|...|expiry".
Enter a value.
authorization> ****

Keep this "remote" remote?
y) Yes this is OK
e) Edit this remote
d) Delete this remote
y/e/d> y
```

### Obtaining an authorization token

The easiest way is to copy the `Authorization` header value from an existing
[OpenList](https://github.com/OpenListTeam/OpenList) 139 storage config — the
field is already a `Basic ` + base64 string.

Alternatively, log in to <https://yun.139.com> in a browser, open the network
panel, look for any request to `*.yun.139.com` and copy the value of the
`Authorization` request header. The value starts with `Basic ` followed by
the base64 of `pc:<phone-number>:<token>|...|<expiry-millis>`.

### Configuration reference

In addition to the standard options, the backend exposes:

- `--yun139-space`: which storage space to use. `personal` (default) for the
  new personal cloud (新个人云), or `family` for the new family cloud
  (新家庭云).
- `--yun139-family-id`: the ID of a family cloud. Required when
  `--yun139-space=family`.
- `--yun139-root-folder-id`: the folder ID to use as the root. Leave blank
  for the top level of the space. Family-cloud users can paste the output of
  OpenList's "family root path" here.
- `--yun139-encoding`: encoding to use for filenames. The default `Slash,LtGt,DoubleQuote,Colon,Question,Asterisk,Pipe,BackSlash,Del,Ctl,InvalidUtf8,RAngle,LAngle,SquareBracket,Hash,Pct,SemiColon,SingleQuote,BackQuote` matches the
  restrictions 139 applies to file names.
- `--yun139-part-size`: the multipart upload chunk size. Default 100 MiB
  (matches the server's preferred upload unit).
- `--yun139-upload-concurrency`: maximum number of part uploads to run in
  parallel. Default 4.
- `--yun139-hard-delete`: delete files permanently instead of moving them to
  the recycle bin.

### SHA-256 rapid upload (秒传)

Rclone masquerades as the official 139 PC client on every request to the
personal cloud. This is required for the server to honour the `sha256` field
in `/file/create` and short-circuit the upload to a hash match (秒传). The
masquerade is automatic and not user-configurable.

### Sharing an account with OpenList

The token is shared with OpenList. Refresh-token conflicts can be avoided by
making sure only one program refreshes at a time. The yun139 backend refreshes
the token only when the cached one is within 5 minutes of expiry, so running
both programs side-by-side is usually safe.

### Limitations

- The personal cloud's `/file/getDownloadUrl` URLs are time-limited (typically
  15 minutes). rclone refreshes them on demand and caches them per object
  call, so streaming a large file should not need more than one refresh.
- The family cloud's rename / move API requires the server-side path
  (`root:/x/y`) of every involved directory. rclone learns these paths
  incrementally as it lists parents; a Move against a never-listed directory
  may need a List of the parent first.
- Multi-threaded copy (the chunked copy engine) is currently disabled. Copy
  of a single file falls back to a sequential upload and is correct, but
  slower than `--transfers 1 --checkers 1` would otherwise be.
- 139 does not expose a per-folder total size; folder size always shows 0.
